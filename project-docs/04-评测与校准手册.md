# 评测与校准手册

> 这一步决定站点"选得准不准"，也是框架最有价值的方法论：门槛不许拍脑袋，用标注样本说话。需要业务对接人投入 1~2 天标注。

## 1. 准备 gold 样本集（100~200 条）

从**自己的信源**里挑 100~200 条资料，一条一条标"该选 / 不该选"，存成 `.data/gold.jsonl`（`.data/` 不进 Git）。每行一条：

```json
{"caseId":"cus-001","material":{"title":"海关总署公告2026年第XX号","originalTitle":null,"publishedAt":"2026-10-01T09:00:00+08:00","sourceName":"海关总署","bodyZh":null,"bodyOriginal":"公告正文……"},"sourceFacts":{"sourceKind":"web_list","sourceTier":"T1","firstParty":true,"language":"zh"},"samplingContext":{"benchmarkSplit":"development","samplingStratum":"税率调整"},"gold":{"decision":"select"}}
```

| 字段 | 说明 |
|---|---|
| `material` | 标题、发布时间、信源名、正文（中文放 `bodyZh`，原文放 `bodyOriginal`，有一个即可） |
| `sourceFacts.sourceKind` | `rss` / `web_list` / `mp_account` 等，与实际信源一致 |
| `sourceFacts.sourceTier` | `T1` / `T1_5` / `T2`，决定用哪档门槛评 |
| `samplingContext.samplingStratum` | 自定义分组：`税率调整` `出口管制` `口岸动态` `运价` `营销软文`……用来看错在哪一类 |
| `benchmarkSplit` | `development` 调提示词用；`holdout` 留出集最后验一次 |
| `gold.decision` | `select` 该选 / `reject` 不该选 / `either` 两可（不计入准确率） |

**标注口径（内部试用版，业务对接人最终确定）：**
- "该选" = 团队里至少一半人当天会点开看，或包含会改变申报动作的信息（新公告、税率变化、实施日期、管制清单）；
- "不该选" = 揽货广告、例行行情、无新事实的旧政科普、与进出口无关的泛宏观；
- **多放难例**：差一点该选/不该选的。一眼能判断的放太多，准确率虚高；
- 留出集占两成左右，调提示词只看开发集，最后用留出集验收，防止把提示词调成只会做这几道题；
- 标注人就是以后读这个站的人（关务/货代岗）。

## 2. 跑评测

```bash
node --env-file=.env scripts/eval-selection.ts --gold .data/gold.jsonl --split development --label "v1 初版评分标准"
```

输出：
- 准确率、查准率（选出的多少是对的）、查全率（该选的多少被选上）；
- 门槛 40~90 每 2 分一档各自的结果；
- 判错条目完整报告写 `.data/eval/`，并导入后台 SelectBench。

常用参数：`--models default,deepseek-flash` 同批比几个模型；`--n 200` 限量；`--split holdout` 只跑留出集。回执机制保证：同样的输入+提示词重跑不花钱，只有改过的部分产生新调用。

## 3. 看错例 → 改标准 → 再跑（循环）

在后台 SelectBench 逐条看判错资料和模型理由：

- **该选没选上** → 评分标准没说清这类为什么重要：写进 `selection-score.md` 的"必须正常评价"，给例子（例：官方公告即使条文平淡也是节点；实施日期与过渡期安排是核心价值）；
- **不该选却选上** → 噪声没压住：写进"必须压住"（例：货代揽货广告 `sig ≤ 2`）；
- **整体偏松/偏紧且错例分数贴着门槛** → 这时候才动 `industry/selection.ts` 的门槛。**先改标准再动门槛**：门槛只能整体平移，解决不了"哪一类判错"。

每改一版跑一遍并打新 `--label`，SelectBench 里看各版本对比。提示词版本=内容哈希，改了只影响新资料。

## 4. 定稿与验收

1. 开发集上达标（准确率参考目标 ≥ 85%，具体复盘时定）后，跑一遍 `--split holdout` 验收；
2. 把最终门槛写回 `industry/selection.ts`；
3. 上线后持续收集漏报/误报，积累一个月再扩 gold 集重评（选择性偏移：政策热点会随时间漂移）。

## 5. 换模型前先比一比

后台"模型与评测"页可切换每步模型（只影响新任务）。换评分模型前：

```bash
node --env-file=.env scripts/eval-selection.ts --gold .data/gold.jsonl --models default,qwen3.8-flash --label "评分模型对比"
```

同一批样本同一标准下比准确率和成本，再决定。
