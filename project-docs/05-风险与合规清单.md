# 风险与合规清单

> 内部试用阶段就要守住的底线；公开阶段再逐条升级。框架的默认行为已经替我们挡掉大半，列出来说明"为什么不能改掉这些默认"。

## 1. 内容准确性风险（本行业最重的一条）

关务信息错了会误导业务决策（税率用错、错过实施日期、误读政策意图）。应对：

- **框架纪律必须保留**：每条精选链接原文；站内默认只显示摘要（`site_fulltext: false`）；标题摘要不得出现原文没有的机构名（`IDENTITY_LEXICON` 兜底）。
- **关务版新增纪律（写进提示词）**：摘要必须写清公告号与发布日期、**实施/生效日期**分开写；税率、税号、品类等数字照抄原文不换算不汇总；不解读法律后果、不替监管补全政策意图；标题与正文冲突以正文为准。
- **页面免责声明**：关于页/条款页写明"内容为自动聚合摘要，仅供内部参考，不构成合规建议，以官方公告原文为准"。
- **模型评分不替代人**：上线后前两周，业务对接人每天扫一遍精选，把误报记进反馈——这正是框架后台"反馈"和 SelectBench 存在的目的。

## 2. 版权

- 默认只摘要+链接，原文版权归原作者；`RSS full.xml` 全文输出保持关闭。
- `industry/site.ts` 的 `copyright` 已含"来源方可要求更正、下架"的说明，公开阶段按正式主体改写。
- 公众号内容同样只摘要链接（`mp_account` 采集走正规第三方接口，不爬）。

## 3. 数据与访问安全

- `.env`、`.data/`（含 gold 样本、评测报告）不进 Git；四个必填密钥全部 `openssl rand -hex 32` 随机生成。
- 内部试用：腾讯云安全组限公司 IP/VPN；`SITE_URL` 用内网地址；不做备案。
- 后台仅管理员密码（可选飞书账号登录）；公开内容匿名，读者收藏/已读只在浏览器本地。
- 不要关闭 `IMG_PROXY_SIGN_SECRET` 图片代理签名；没有反向代理时保持 `TRUST_PROXY=false`（防止伪造地址绕过登录限次）。
- 出口管制、制裁类信息在内部站同样敏感：控制站点访问范围，不外发。

| 服务 | 用途 | 风险与应对 |
|---|---|---|
| 极致了（Dajiala） | 公众号采集 | 按请求计费；启用前必设预算日上限；停服只影响公众号源，官方源不受影响 |
| SocialData | X 采集 | 内部试用不用，无依赖 |

## 6. 项目过程风险

| 风险 | 应对 |
|---|---|
| 上游（AIHOT）单维护者、刚开源，更新节奏未知 | fork 持有；只改 `industry/` 保证 `git pull` 冲突最小；关键提交本地留档 |
| 政府网站改版导致 `web_list` 抓取失败 | 框架自带信源健康监控与告警（接飞书告警群），失败可定位到源 |
| 标注质量差导致门槛校准失真 | 标注人固定 + 标注口径文档化（04 文档），难例优先 |
| 热度漂移（某段时间无大事，日报"没东西"） | 正常现象；T1 门槛偏松的设计就是保下限，复盘时看漏报而非条数 |
| 模型内容过滤拒绝（如涉制裁类文本） | 框架已处理：被拒资料不精选不报错，进入"全部动态"待人工；后台可见 refused 记录 |
