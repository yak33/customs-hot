# 内部试用部署方案（腾讯云）

> 目标：内部试用阶段**不开公网站点**，产出主要走飞书群推送；降低备案、品牌、合规的前置负担。命令均来自上游 `docs/deploy.md` 与 `.env.example`，以实际仓库为准。

## 0. 服务器要求

- 腾讯云 Linux（带 Docker + Docker Compose），**2 核 4G 起步**（构建镜像时吃内存，4G 稳妥）。
- 数据库在容器里（PostgreSQL 17），不对外开端口；数据在 Docker 卷 `db` / `data` 里，`docker compose down` 不删卷。

## 1. 阶段 0：先跑 AI 示范站（半天）

改造前先原样跑一遍示范站，验证服务器、网络、模型 key 都没问题，也直观看到"精选质量长什么样"：

```bash
git clone https://github.com/KKKKhazix/AIHOT.git aihot-demo
cd aihot-demo
node scripts/init-env.ts --llm-key <模型Key>     # 生成 .env，打印随机管理员密码（只打印一次）
docker compose build --build-arg NPM_REGISTRY=https://registry.npmmirror.com
docker compose up -d
# 打开 http://服务器IP:3000 ，后台 /admin
```

- 首次启动自动迁移+导入示范信源，约半小时处理完首批 150 条资料。
- 海外信源抓不到时，`.env` 加 `EGRESS_PROXY_URL`（只影响抓取，模型调用不走它）。
- 模型接口国内直连：智谱 `LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4`、`LLM_MODEL=glm-5.3-flash`（DeepSeek、千问同理，见 `.env.example`）。

体验确认后停掉 demo（`docker compose down`，不占资源），开始改造。

## 2. 阶段 1：部署关务版

用 fork 仓库 clone 出改造后的代码，`.env` 关键项：

```bash
SITE_URL=http://<服务器内网IP>:3000     # 内部试用用 IP；正式公开时换 https 域名
ADMIN_PASSWORD=<openssl rand -hex 32 生成>
SESSION_SECRET=<同上>
IMG_PROXY_SIGN_SECRET=<同上>
POSTGRES_PASSWORD=<同上>
LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4
LLM_API_KEY=<智谱Key>
LLM_MODEL=glm-5.3-flash
EGRESS_PROXY_URL=<如需抓海外源才填>
TRUST_PROXY=false                      # 没有反向代理就保持 false
COLLECT_ENABLED=true                   # 调试界面时先设 false，确认 UI 后再打开
MODEL_CALLS_ENABLED=true               # 同上
```

```bash
docker compose build --build-arg NPM_REGISTRY=https://registry.npmmirror.com
docker compose up -d
```

**网络访问控制（内部试用不做备案）**：腾讯云安全组把 3000 端口限制为公司出口 IP / VPN 网段；或干脆不开公网，仅内网 + 飞书推送为主入口。

## 3. 飞书集成（内部试用的主要产出通道）

按 `.env.example`，两件事是独立的：

**a) 精选推送到群（必须接，配置最简单）**

1. 目标群添加"群机器人"，拿 webhook 地址；
2. `.env`：`FEISHU_CONTENT_PUSH_ENABLED=true` + `FEISHU_PUSH_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxx`；
3. 后台"设置 → 推送目标"里启用。

效果：每天最精选的几条推到集团群，群消息附站点链接。

**b) 系统告警（建议接）**

信源抓取失败、站点停止收录等告警转发到内部群，需要飞书自建应用：`FEISHU_INTERNAL_ENABLED=true` + `FEISHU_APP_ID/APP_SECRET/INTERNAL_CHAT_ID/ALERT_CHAT_ID`。

**c) 可选**：飞书账号登录后台（`FEISHU_LOGIN_APP_ID/SECRET` + `ADMIN_FEISHU_UNION_IDS`），免管理员密码共享。

## 4. 备份与预算（上线前配置好）

- **备份**：`.env` 填 `DB_BACKUP_STORE_*`（腾讯云 COS 就是 S3 兼容的，文档明确支持），每天 04:10 自动备份；随时可手动 `docker compose exec -T db pg_dump -U aihot aihot | gzip > backup.sql.gz`。
- **预算熔断**：后台"设置 → 预算"给每个付费服务设每分钟/每小时/每天上限，超了自动暂停；填 0 立即停用该服务。**模型服务设个保守日上限，公众号采集启用前必设。**
- **更新**：`git pull && docker compose up -d --build`，迁移自动执行。

## 5. 模型配置策略（内部试用从简）

- 内部试用：全部步骤用同一个 flash 档模型（智谱 GLM），够用且最省心；评分环节框架对 GLM 有专门调优，效果好。
- 省钱进阶（可选，照上游自己的分工）：`PREFILTER_MODEL=qwen3.7-flash`、`SCORE_MODEL=glm-5.3-flash-selection`、`SUMMARIZE_MODEL=deepseek-flash`……后台"模型与评测"页能看每步调用量和 token，有数据再优化，不提前做。
- 向量召回（事件归组更准，可选）：不填也能跑，只是归组少一路线索；有阿里云百炼 key 填 `DASHSCOPE_API_KEY` 即可。

## 6. 成本观察口径

- 参考：上游示范信源首批 152 条 ≈ 930 次模型调用；关务信源日均量远小于 AI 资讯，成本应明显低。
- 观察位置：后台"模型与评测"页看每步调用次数与 token；"运行"页看定时任务结果。
- 前 3 天每天看一次，得到"每天大约多少钱"的实测数，再决定是否调信源频率。

## 7. 内部试用成功指标（试用 2~4 周后复盘）

| 指标 | 目标 | 看哪里 |
|---|---|---|
| 信源抓取成功率 | ≥ 95% | 后台"信源"页 |
| 每日精选条数 | 5~20 条，无整天空报/爆量 | 首页/日报 |
| 误报率（不该选的混进来） | ≤ 10% | 团队主观评价 + SelectBench 抽查 |
| 漏报（事后发现该报没报） | 每周 ≤ 1 条 | 团队反馈登记 |
| 飞书群互动 | 有人点开、有人转发 | 群内观察 |
| 日均模型成本 | 拿到实测数且稳定 | 后台"模型与评测" |

**决策点（试用结束复盘会）**：继续内部用（补信源、调门槛）→ 面向公开行业站（备案、品牌、条款、运营）→ 放弃。用数据说话，不用感觉。
