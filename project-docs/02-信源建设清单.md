# 信源建设清单

> 改造中最重的一块工作在这里。框架支持 6 种信源类型，但**清单里所有"待核实"项都必须逐个试抓确认**——本文档只列候选和核实方法，不臆造 RSS 地址。
> 上线后日常维护走后台"信源"页：新建、试抓、调频率、看失败原因，抓挂了会告警。

## 0. 信源类型速查（上游 `docs/sources.md` 为准）

| kind | 说明 | 依赖 |
|---|---|---|
| `rss` | RSS/Atom 订阅 | 无 |
| `web_list` | 网页列表页 + CSS 选择器 | 无（政府网站主要靠它） |
| `json_list` | JSON 接口 | 无 |
| `x_search` | X（推特）账号 | SocialData key，按请求计费 |
| `mp_account` | 微信公众号 | 极致了（Dajiala）key，按请求计费 |
| `external` | 外部推送（`POST /api/ingest/items`，配 `INGEST_TOKEN`） | 无 |

## 1. 信源分级与参与模式

| 分级 | 定义 | 本行业对应 | 门槛策略 |
|---|---|---|---|
| `T1` | 官方一手 | 海关总署、税委会、商务部、税务总局等官网 | 门槛最低，官方公告宁可多看 |
| `T1_5` | 准官方 | 地方海关、单一窗口、港口集团、官方公众号 | 中 |
| `T2` | 媒体与个人 | 行业媒体、公众号解读 | 门槛最高 |
| `EXCLUDE_MP` | 不参与精选 | 广告号、营销号 | 只进"全部动态" |

`participation_mode`：官方源用 `editorial`（进精选）；大量互相转载的市场类媒体可设 `hot_signal`（只算热度证据）；一律保持 `site_fulltext: false`（版权与合规，见 05 文档）。

### 探测记录（2026-09-29）

- **单一窗口**（探测：K3，复核：本方）：SPA 站，列表数据来自 `POST /access/ui/SW-SITE-FRONT/Article001`（`Data` 是字符串化 JSON；`catalogid`: `tzgg`=通知公告 / `zcfg`=政策法规）；响应字段 `data.data[] → articleid/title/summary/releasetime(毫秒)`；列表接口的 `bodytext` 字段为空，详情正文需 `Article002`，当前折中 `summaryIsBody: true` 用一句话摘要当正文，够预筛评分用。浏览器带的反爬签名参数服务端不校验，裸调可用。风险：政府站内部接口，改版即失效。
- **海关总署**（探测：本方）：首页与"海关法规"栏目页（`/customs/302249/302266/index.html`）是静态发布，裸 HTTP 可抓；总署公告就发布在该栏目列表里（无独立"总署公告"列表页，旧路径 `302267` 被 WAF 拦截返回 412）。列表结构 `ul.news_list li > a(标题+链接) + span(发布日期)`，已用框架 `fromHtml` 解析器离线实测：10 条候选、标题/绝对链接/日期全部正确。**注意**：同站"最新文件""政策解读""统计快讯"等栏目页会被 WAF 挑战（412，约 2KB 的 JS 挑战页），裸客户端抓不到——新栏目接入前必须先实测，不能默认整站可抓。
- **税委会公告**（探测：本方）：公告发布在财政部关税司 `gss.mof.gov.cn` 的"政策发布"栏目（`/gzdt/zhengcefabu/`，税委会公告与关税政策文件混合，一个月几条量级），静态 HTML，结构 `ul.liBox li > a(标题+链接) + span(日期)`，框架解析器离线实测 10 条全对。**坑**：该站文章链接是相对当前目录的 `./202604/x.htm` 形式，所以这条信源**不能配 `baseUrl`**（相对链接要相对列表页 URL 解析），已在 sources.json 中体现。
- **商务部**（探测：本方）：主站是 JPAAS 架构。两个能用的静态入口：① 贸易救济子站 `trb.mofcom.gov.cn` 首页——"贸易救济调查"（反倾销/反补贴/保障措施）、"贸易壁垒调查"、"贸易摩擦应对"三个区块静态带数据且都有日期，条目分布在 `bjgList_01` 和无 class 的 `ul` 里，所以用 `itemSelector: "li"` + `allowUrlPrefixes` 按 `/myjjdc/`、`/mybldc/`、`/mymcyd/` 三条路径过滤，实测 37 条全对；② 主站新闻发布聚合页 `/xwfb/index.html`，7 个子栏目（例行发布会、发言人谈话等）静态带数据，`ul.txtList_01 li` 实测 30 条全对。**不可用**：主站"政策发布"栏目 `/zwgk/zcfb/` 的列表走 `GET /api-gateway/jpaas-publish-server/front/page/build/unit`，返回 JSON 里 `data.html` 字段是 HTML 片段——框架 `json_list` 只能解析数组型 JSON，不支持"字段里是 HTML"，故未接入（内容与贸易救济子站高度重合，损失可接受）。另注意 trb 子站对 Windows curl（schannel）会 SSL 重协商失败，但 Node fetch 正常，框架抓取不受影响。
- **税务总局**（探测：本方，暂缓）："最新文件"栏目列表页静态可抓但条目**只有文号没有日期**；详情页 `content.html` 是通用模板壳，正文按 URL 动态加载，裸 HTML 里拿不到发布日期（detail 补日期走不通）；政策法规库 `fgk.chinatax.gov.cn` 列表页也是骨架；统一搜索接口 `www.chinatax.gov.cn/search5/search/s` 存在（文件库检索走它），但参数组合未摸通（试 `column=政策文件` 返回 total=0），且属搜索型接口、不适合做增量列表。**结论**：需要后续摸通 search5 参数（或改走 `external` 外部推送）再接入，暂缓。

## 5. 接入操作与核实方法

每个候选信源的核实动作（后台"信源"页 → 新建 → 试抓）：

1. 确认列表页 URL 和翻页方式；打开页面开发者工具看列表项的选择器（`web_list` 需要）。
2. 试抓后检查：标题完整、原文链接对、发布时间对（时间错会导致"旧文归档"规则误伤）。
3. 设 `interval_minutes`：T1 官方 30~60，T2 媒体 120~240。别把几十个源全设 15 分钟，无意义且容易触发对方反爬。
4. 观察 2~3 天抓取成功率，失败原因在后台"信源"页可见（改版、反爬、超时）。

**补充选项（先不用）**：RSSHub 可以把没有 RSS 的网站转成 RSS，但要自建维护一个额外组件；`web_list` 够用时不引入。

## 6. 内部通知通道（可选亮点）

`INGEST_TOKEN` 打开后，集团的报关行通知、口岸临时通知可以脚本化 `POST /api/ingest/items` 推进站里（`kind: external`），和外部信源一起进归组和日报——内部试用阶段如果有这类人工通知流，值得接。

## 7. 待业务侧确认的问题（一次性问清）

1. 集团主要业务口岸/关区是哪几个？→ 决定地方海关信源名单。
2. 主要出口品类是什么？→ 决定 TOPIC_TAGS 和评分"共振面"的口径（汽车出口、大宗、冷链权重完全不同）。
3. 团队现在每天从哪里获取这些信息？→ 那些渠道就是最好的信源候选清单。
4. 公众号付费通道（极致了）预算是否批准？→ 决定 P1-13 是否启用。
