# 上游项目 AIHOT 分析

> 基于 2026-09-29 对 [KKKKhazix/AIHOT](https://github.com/KKKKhazix/AIHOT) 仓库的分析（main 分支，568 个文件）。当时该项目创建仅一天，2400+ stars、692 forks，MIT 协议。

## 一句话

自托管的"自动找热点、自动写日报"网站框架：接上自己的信源和精选标准，就是一个行业热点站，产出网页、RSS、公开 API、MCP 和日报/周报/月报。默认配置是一个跑了很久的 AI 行业示范站。

## 架构（三个进程 + PostgreSQL）

| 进程 | 技术栈 | 职责 |
|---|---|---|
| `apps/api` | Fastify | 网站接口、公开 API v1、RSS、MCP、后台、图片代理、OG 分享图 |
| `apps/worker` | pg-boss 队列 | 抓信源、调模型、归组、热度、日报、告警、备份清理 |
| `apps/web` | React Router 8 SSR + Tailwind 4 | 前端，只通过 HTTP 读 api，不碰数据库 |

数据流：

```
信源(RSS/网页/JSON/X/公众号/外部推送) → 采集判重抓原文 → 预筛 → 两次独立评分
→ 写作(标题/摘要/理由) → 结构化(分类/标签/主体/事实) → 事件归组 → 公开读取层 → 各出口
```

技术栈较新：Node.js 24 直接运行 TypeScript（后端零构建）、TypeScript 7、zod 4 校验所有模型输出、postgres.js 原生 SQL 无 ORM。部署是 Docker Compose 五容器（db / setup / api / worker / web）+ 可选 Caddy HTTPS。

## 数据流水线（一条资料怎么变成精选）

1. **收进来**：同网址同内容只留一份；只有标题的先抓原文页面。
2. **预筛**（`prefilter.md`）：宽召回，只拦明确无关的 BLOCK；UNKNOWN 继续走。
3. **评分**（`selection-score.md`）：同一评分标准**独立打两次分**（0–100），两次之和 ≥ 2 × 信源分级门槛才入选；门槛 T1/T1.5/T2 分级不同（默认 60/65/76）。
4. **写作**：入选和差一点入选的用"内容理解"写中文标题、答案先行摘要、推荐理由、标签；其余用便宜的标题摘要提示词。
5. **结构化**：分类、标签、主体机构、事实帧（谁做了什么），供主题页和事件归组用。
6. **归组**：不同来源的同一件事归成一个事件，事件页有综述；"热门"按事件排。
7. **日报 08:00 / 周报周一 10:00 / 月报每月 1 日**，跨刊期边界有候选池机制防漏稿。

提示词版本 = 内容哈希：改提示词只影响新资料，已判过的不会重算。

## 工程上最值钱的三个设计

**1. 付费请求回执系统（`packages/backend/src/providers/receipts.ts`）**。每个付费请求（模型、X、公众号、Jina）先按 `logical_key = hash(服务, 用途, 模型, 输入, attemptTag)` 落占位回执再调用；响应先持久化再做业务写入；"结果未知"（超时）不自动重发，30 分钟后只自动放行一次；每个服务有分钟/小时/天三级预算熔断，并发用 `pg_advisory_xact_lock` 串行化。重启、重试都复用已付费结果。

**2. 提示词评测纪律**。手工标 100–200 条 gold 样本 → `scripts/eval-selection.ts` 出准确率/查准/查全 + 门槛 40–90 扫描 → 错例进后台 SelectBench 对比迭代。把 ML 评测方法论用于提示词调优，是开源里少见的东西。

**3. 行业包分离**。所有领域相关的东西（站名、分类、信源、门槛、18+ 个提示词、品牌、条款页）集中在 `industry/` 目录，换行业不动 `apps/` 和 `packages/`。

## 其他值得知道的

- **测试**：33 个测试文件，全部不访问外部服务（本地假服务应答），含优雅停机测试。改了 `industry/taxonomy.ts` 后，部分引用示例行业（ai-models、"模型发布"等）的测试要同步换例子。
- **安全姿态**：页面阅读不触发模型调用；公开内容匿名；后台仅管理员；信源默认只展示摘要+原文链接（`site_fulltext` 默认关）。
- **飞书**：精选推送群机器人（webhook）、告警走自建应用、甚至可用飞书账号登录后台。
- **成本**：官方数据——示范信源首批 152 条资料约 930 次模型调用；之后每天取决于信源更新量。
- **与 GLM 的耦合痕迹**：评分调用对 `glm-5.3-flash-selection` 有专门参数（temperature 1、65k tokens、高推理），内容过滤错误识别按智谱 1301 错误码写。用其他模型可以，但评分环节用 GLM 效果最稳。

## 对我们选它的意义

- 关务行业"信息分散 + 时效敏感 + 政策驱动"的特征，和框架的价值公式（读者注意力有限 + 时效就是钱）高度匹配；
- 它是中国本土化的（北京时间、公众号采集、飞书推送、备案指引），内部试用阶段几乎零额外适配；
- 真正的工程难点（回执/预算/归组/评测）它都解决了，剩下的是行业 KnowHow——那正是我们要投入的部分。
